## 一、项目简介
云购生活（虚构）是一家全国连锁新零售企业，采用"线上商城 + 线下门店"融合经营模式，业务覆盖全国 15 个省份、60 家线下门店，主营八大品类。
本项目从 0 到 1 搭建一套企业级数据仓库与经营分析可视化系统，实现对海量经营数据的统一采集、清洗、建模、分析与可视化呈现。

### 团队协作规范
- **分支策略**：`main` 主分支保护，功能开发使用 `feat/xxx` 分支，合并前需通过代码评审。
- **提交规范**：采用 Conventional Commits 规范——`feat:` 新功能、`fix:` 修复、`docs:` 文档、`style:` 格式、`refactor:` 重构、`test:` 测试、`chore:` 构建/工具。
- **代码评审**：所有合并请求至少 1 名团队成员 review 通过后才能合入 main。
- **同步频率**：每日至少 `git pull` 一次，开发完成及时 `push`，避免长期本地分支导致冲突。

## 三、项目目标
- 数据层：完成 6 张业务表采集导入，识别并清洗五大类脏数据，输出清洗前后数据质量对比报告。
- 数仓层：Hive 搭建 ODS → DWD → DWS → ADS 四层数仓，完成维度建模与 ETL 全流程。
- 分析层：ADS 层 KPI 指标计算与探索性分析，Python 时间序列预测建模。
- 智能层：大模型 API + LangChain 构建 NL2SQL 自然语言查询接口。
- 展示层：Apache Superset + ECharts 构建交互式仪表板与数据大屏。
- 工程层：Git 版本控制 + Docker Compose 一键部署。

## 四、技术栈
Apache Hive / MySQL / ClickHouse(可选) / Python / 大模型API / Apache Superset / ECharts / Streamlit / Docker Compose / Git

## 七、数据说明
6 张模拟 CSV 数据总量约 11 万条，已刻意植入五大类脏数据（缺失、重复、异常、格式不一致、业务逻辑错误），供清洗实战。
- ods_user.csv：1,000 行（用户信息）
- ods_product.csv：600 行（商品信息）
- ods_store.csv：60 行（门店信息）
- ods_order.csv：15,600 行（订单主表，含重复订单）
- ods_order_item.csv：37,549 行（订单明细）
- ods_user_behavior.csv：60,000 行（用户行为日志）
