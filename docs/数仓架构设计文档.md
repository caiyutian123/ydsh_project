# 云购生活数据仓库架构设计文档

> 团队：数据先锋队（一人多岗）　撰写：蔡雨田
> 版本：v1.0　日期：2026-11-02
> 环境：Docker Compose（MySQL 8.0 + Hive Metastore + HiveServer2，Hive 4.0.0）

---

## 1. 设计目标

为"云购生活"新零售业务构建企业级数据仓库，解决 ODS 源数据中存在的**枚举值不统一、异常值、格式混乱、字段冗余、主键重复**等质量问题，为上层经营分析提供**干净、一致、可复用**的数据底座。

设计原则：

| 原则 | 说明 |
|------|------|
| 分层解耦 | ODS → DWD → DWS → ADS 四层，职责单一、血缘清晰 |
| 维度建模 | DWD 层采用星型模型，事实表 + 维度表 |
| 存储优化 | DWD 层统一 ORC 列式存储；大事实表分区 / 分桶 |
| 编码映射 | 枚举类维度建立编码映射表，事实表冗余编码字段便于关联 |
| 命名规范 | 统一前缀 + 统一分隔符，见第 6 节 |

## 2. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                        应用层                                │
│   经营分析简报 / 可视化报表 / 自助取数                         │
└───────────────────────────▲─────────────────────────────────┘
                            │
┌───────────────────────────┴─────────────────────────────────┐
│  ADS 应用数据层（ydsh_ads）                                   │
│   面向具体报表/应用的结果表（如：品类销售日报、渠道转化漏斗）      │
├───────────────────────────▲─────────────────────────────────┤
│  DWS 汇总数据层（ydsh_dws）                                   │
│   按主题轻度汇总：用户日汇总 / 商品日汇总 / 门店日汇总           │
├───────────────────────────▲─────────────────────────────────┤
│  DWD 明细数据层（ydsh_dwd）                                   │
│   清洗后的明细事实表 + 一致性维度表（星型模型，ORC 存储）         │
│   dwd_order │ dwd_order_item │ dwd_user_behavior             │
│   dim_user  │ dim_product    │ dim_store │ dim_date          │
│   dim_member_level │ dim_pay_type（编码映射）                  │
├───────────────────────────▲─────────────────────────────────┤
│  ODS 操作数据层（ydsh_ods）                                   │
│   源数据原样接入（csv 文本），清洗中间态 stg_* / cln_*          │
│   ods_user │ ods_product │ ods_store │                       │
│   ods_order │ ods_order_item │ ods_user_behavior              │
└───────────────────────────▲─────────────────────────────────┘
                            │
┌───────────────────────────┴─────────────────────────────────┐
│  数据源：业务系统导出的 6 张 csv 文件（data/ 目录）              │
└─────────────────────────────────────────────────────────────┘
```

### 分层职责

| 层级 | 库名 | 职责 | 数据特点 |
|------|------|------|----------|
| ODS | ydsh_ods | 源数据原样落地 + 清洗中间过程（stg_/cln_） | 文本存储，保留原始值 |
| DWD | ydsh_dwd | 清洗后明细 + 维度建模 | ORC 列存，分区/分桶 |
| DWS | ydsh_dws | 按主题（用户/商品/门店/日期）轻度汇总 | 预聚合指标 |
| ADS | ydsh_ads | 面向具体报表与应用的最终结果 | 可直接对接 BI |

## 3. DWD 层星型模型

```
              dim_user                    dim_product
           (用户维度)                     (商品维度)
          user_id (PK)                   product_id (PK)
          gender / age                   category / brand
          province / city / region       price / cost
          member_level(+code)                ▲
                 ▲                             │
                 │                             │
dim_date         │        dwd_order_item       │
 (日期维度)       │       (订单明细事实·分桶)     │
 date_id (PK)    │       item_id (PK)          │
 year/quarter    └────────order_id (FK)        │
 month/day               product_id (FK)───────┘
 week_of_year            quantity / unit_price
        ▲                        ▲
        │                        │
        │      dwd_order         │
        │    (订单事实·按日分区)   │
        │    order_id (PK)       │
        └────order_date          │
             user_id (FK)────────┘
             store_id (FK)─── dim_store (门店维度)
             order_timestamp     store_id (PK)
             pay_amount          province / city / district
             discount_amount     manager
             pay_type(+code)
             order_status / channel

        dwd_user_behavior (行为事实·按行为日期分区)
        behavior_id (PK) / user_id (FK) / product_id (FK)
        behavior_type / behavior_time / session_id
```

三个事实表共享 dim_user、dim_product、dim_store、dim_date 四套一致性维度，
构成典型的**星型模型 + 一致性维度总线**。

## 4. DWD 层表清单

### 4.1 维度表

| 表名 | 粒度 | 关键字段 | 说明 |
|------|------|----------|------|
| dim_user | 一个用户一行 | user_id, gender, age, region, member_level, member_level_code | region=省份-城市 合并字段；等级冗余编码 |
| dim_product | 一个商品一行 | product_id, category, sub_category, brand, price | category 已 trim |
| dim_store | 一个门店一行 | store_id, province, city, district, manager | — |
| dim_date | 一天一行 | date_id, year, quarter, month, week_of_year, is_weekend | 程序生成 2024 全年 |
| dim_member_level | 一个等级一行 | level_code, level_name | 编码映射（1~4） |
| dim_pay_type | 一种支付方式一行 | pay_type_code, pay_type_name | 编码映射（1~5） |

### 4.2 事实表

| 表名 | 粒度 | 存储策略 | 说明 |
|------|------|----------|------|
| dwd_order | 一笔订单一行 | ORC + 按 order_date 动态分区 | order_timestamp 合并字段；pay_type_code 冗余编码；order_id 已去重 |
| dwd_order_item | 一行明细一行 | ORC + 按 order_id 分 8 桶 | 与 dwd_order 桶键关联，优化 JOIN |
| dwd_user_behavior | 一次行为一行 | ORC + 按 behavior_date 动态分区 | behavior_time 补齐秒位 |

**分区设计**：订单与行为为时间增长型大表，按日期分区可按天裁剪扫描量；
**分桶设计**：dwd_order_item 按 order_id 分桶，为后续与 dwd_order 的 SMB（Sort-Merge-Bucket）关联做准备。

## 5. 数据流与 ETL 链路

```
data/*.csv
   │  LOAD DATA（第1周）
   ▼
ydsh_ods.ods_*                    —— 原样接入
   │  sql/clean/02_enum_standardize.sql   （枚举映射、剔除表头行）
   ▼
ydsh_ods.stg_*
   │  sql/clean/03_anomaly_format.sql     （异常修复、格式统一、缺失补全）
   ▼
ydsh_ods.cln_*
   │  sql/clean/04_field_merge_mapping.sql（字段合并 + 编码映射表）
   ▼
ydsh_ods.cln_order_final  +  ydsh_dwd.dim_member_level / dim_pay_type
   │  sql/dwd/create_dwd.sql + sql/dwd/load_dwd.sql（建模 + 动态分区加载 + 去重）
   ▼
ydsh_dwd.dim_* / dwd_*
   │  后续：按主题汇总
   ▼
ydsh_dws / ydsh_ads
```

## 6. 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 数据库 | 业务域_层级，小写 | ydsh_ods / ydsh_dwd / ydsh_dws / ydsh_ads |
| ODS 表 | ods_业务实体 | ods_order |
| 清洗中间表 | stg_实体（枚举标准化后）/ cln_实体（全量清洗后） | stg_user / cln_order |
| DWD 事实表 | dwd_业务过程 | dwd_order_item |
| 维度表 | dim_维度实体 | dim_user / dim_date |
| 编码映射表 | dim_枚举域 | dim_member_level / dim_pay_type |
| 字段 | 小写蛇形 | order_timestamp / member_level_code |
| 分区字段 | 字符串日期 yyyy-MM-dd | order_date / behavior_date |
| SQL 文件 | 序号_语义.sql 按目录分层 | sql/clean/02_enum_standardize.sql |

## 7. 存储与性能设计

| 决策 | 选择 | 理由 |
|------|------|------|
| 文件格式 | ORC | 列式存储 + 谓词下推，分析场景 IO 最小 |
| 分区 | dwd_order / dwd_user_behavior 按日期动态分区 | 时间范围查询裁剪分区 |
| 分桶 | dwd_order_item 按 order_id 8 桶 | 大表 JOIN 可走 SMB，避免全量 Shuffle |
| 编码冗余 | 事实表冗余 *_code | 数值关联快于字符串关联，且便于压缩 |
| 动态分区 | hive.exec.dynamic.partition.mode=nonstrict | 单条 INSERT 完成多分区写入 |
