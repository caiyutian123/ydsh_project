# 数据质量预评估报告（第 1 周）

> 评估对象：ODS 层 6 张业务表（ods_user / ods_product / ods_store / ods_order / ods_order_item / ods_user_behavior）
> 评估方法：Hive SQL 从完整性、唯一性、有效性、一致性、准确性五个维度扫描
> 评估脚本：`sql/quality/precheck.sql`

## 一、评估维度说明

| 维度 | 含义 | 评估指标 |
|------|------|----------|
| 完整性 | 字段是否存在缺失 | 空值率 = 空值数 / 总行数 |
| 唯一性 | 主键/唯一键是否重复 | 重复组数、重复行数 |
| 有效性 | 枚举取值是否在合法范围内 | 非法取值数、取值分布 |
| 一致性 | 格式是否统一 | 非标准格式数量 |
| 准确性 | 取值是否合理（范围/正负/超界） | 异常值数量 |

## 七、脏数据分布汇总

| 脏数据类型 | 主要表现 | 主要分布表 |
|------------|----------|------------|
| 缺失值 | 字段为空字符串 / NULL | ods_user(age/email)、ods_product(launch_date) |
| 重复值 | 整行完全重复、主键重复 | ods_order（约 600 条重复） |
| 异常值 | 负金额、超大金额、负年龄、年龄 200 | ods_order、ods_user、ods_product、ods_order_item |
| 格式不一致 | 日期格式、手机号格式混用 | ods_user、ods_order、ods_user_behavior |
| 业务逻辑错误 | 枚举取值中英文/大小写混用 | ods_order(order_status/pay_type)、ods_user(gender/member_level) |

## 八、清洗策略（第 1 周）

| 脏数据类型 | 清洗策略 | 输出目标表 |
|------------|----------|------------|
| ods_user.age 缺失/异常 | 用有效年龄均值填充 | dwd_user |
| ods_user.email 缺失 | 保留空值并添加标记列 email_missing_flag | dwd_user |
| ods_product.launch_date 缺失 | 用库内上架日期众数补全 | dwd_product |
| ods_order.order_id 重复 | ROW_NUMBER() 按 order_id 分区保留一条 | dwd_order |

## 九、评估执行说明

1. 将数据导入 ODS 层后，执行 `sql/quality/precheck.sql`；
2. 将各查询结果填入上表"（执行后填入）"对应位置；
3. 形成完整的《数据质量预评估表》，作为清洗脚本的输入依据；
4. 清洗完成后需再次执行评估，形成清洗前后对比报告。
